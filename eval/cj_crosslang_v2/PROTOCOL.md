## 输入、顺序与门槛

- 已知集 18 题：原 8 道中文开发题和已打开的 v1 10 道留出题。原 40 题作为组件回归。输入哈希见 `freeze.json` 和 v1 freeze 文件。
- 同题基线和候选成对运行，固定随机种子生成交替顺序；记录每对执行顺序和时间。每次使用新会话，禁用语义缓存。

- 候选代码及提示词冻结后，v2 10 道留出题只跑一遍成对评测（技术异常可按固定规则重试）。留出集首次 Hit@5 净增至少 2/10，且无最终答案锚点丢失，才判为泛化成功。若不通过，留出集升级为下一轮已知集，并重新封存新留出集。

## 有效性与计分

- 一侧有效须同时满足 `RUN_FINISHED`、完整首次 `product_search_tool` 参数与结果、完整 `usage.summary` 中的 model_calls/input_tokens/output_tokens，且无网关错误或模型回退。无检索工具调用、工具错误或返回格式不完整，单列无效。
- 一对有一侧无效时，保留两侧原 trace 并完整重跑一对，最多重试两对。仍无效则该题不进成对命中率分母；报告有效对数与全部 18/10 题的覆盖率，门槛不得在缺题时声称通过。
- 网关错误不是检索失败；usage 缺失不是零 token。所有尝试的调用次数及已知 token 单列；若有缺失，总成本标记“未知”，不能给零成本结论。
- 分别记录逐题首次 Hit@5、任一轮 Hit@5、最终答案是否出现锚点 ID 的下降。三者不可互相代替。记录首次 query 原文、Agent 改写 query、category、前五候选 ID 与目标排名、完整 Agent trace。
- CJ 点数和调用次数按实际发生报告，不作为零消耗门槛。本轮检索读取本地快照；如果 Agent 调用了在线 CJ 工具，单列工具、次数及可得成本。
