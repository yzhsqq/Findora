# 升级与运行能力说明

## 各模式的能力

| 能力 | fixture 样例 | CJ 快照 | CJ + Amazon/eBay |
| --- | --- | --- | --- |
| 本站订单、库存事务、人工确认 | 支持本地账本，不含支付 | 不支持 | 不支持 |
| 来源商品链接 | 按样例数据 | CJ 外部购买 | 三平台外部购买；未确认同款 |
| 详情/物流试算 | 样例详情与规则估算 | CJ 按需实时接口 | 仅 CJ 能调用；Amazon/eBay 保持未知 |
| 待购记录 | 不支持 | 支持，非订单 | 仅 CJ |
| 已知预算与材质约束 | 按领域数据校验 | USD 商品价可校验；换汇、材质、运税等不足时 unknown | 同 CJ；不宣称已满足未知条件 |
| 本地 Qdrant | 稠密向量 | 稠密查询融合，无服务端 BM25 | 各平台独立集合 |
| 服务端 Qdrant | 按已有集合能力 | dense + BM25（集合支持时） | 独立集合召回，全局一次精排 |

`GET /commerce/catalog/capabilities` 从装配信息返回能力，不读取商品库。目录浏览局部失败时保留健康平台并给出状态；全部失败返回不可用，不返回假空库。CJ 自由文本检索基础设施故障不会静默改成零结果。

## 数据库升级与回退

1. 暂停写入并停止 API、旧 worker，确认没有在途交易或审批；保留旧版本、原配置与数据目录。
2. 备份全部权威 SQLite 库：订单/会话库（`globex.db`、`findora.db` 或显式 DATABASE_URL）、file 模式 `trade.db`、运行日志、记忆、Skill、证据、能力、Prompt、收藏、待购与 CJ 试算库。派生快照、中文投影和向量索引另记来源版本。外部 DATABASE_URL 使用对应数据库备份流程。
3. 对 SQLite 使用数据库 backup API 或停服后 checkpoint 并确认 WAL 已处理；不要只复制主文件而遗漏未 checkpoint 的记录。备份恢复到隔离目录，检查订单、所有权、待购和会话能读取。
4. 没有显式 URL 时，新目录选择 `findora.db`；仅存在 `globex.db` 时继续使用旧库，不改名、不复制；两库同时存在时拒绝启动。显式 `DATABASE_URL`（或兼容 `MYSQL_URL`）优先，容器同样适用。已有 `.env` 或部署显式配置也应人工核对，自动选择不会覆盖它。
5. 如果确需更名，停服后用 SQLite backup API 生成新库、校验数据并设置显式 URL；保留旧库供回退。不要在两库中交叉写入或自动合并。
6. 升级后用隔离买家检查会话归属、订单查询和待购记录，再开放写入。回退使用相同权威数据库与兼容 schema；若 schema 不兼容，应从停服备份恢复，先保存升级后的新增记录，不直接覆盖。

## Redis 与身份升级

- 品牌升级改变流、组、任务状态、租约等 key 的前缀；新 worker 不会自动接管 `globex:*` 队列。先在旧版本停止接收任务，用旧 worker 排空 queued/pending，并保存队列状态与 Redis 持久化备份，再停止旧 worker。无法排空的任务保留旧环境及显式恢复方案，不把旧 key 批量重命名后交给不同数据源处理。
- 快照 Compose 不默认启动 worker；profile 不会自动停止先前运行的容器。升级时明确停止旧 worker。若以后需要快照 intents 队列，必须用同一来源、索引、Redis 和队列配置同时启用 API/worker，并用全新任务验证；不要混入 fixture 旧任务。
- JWT issuer/audience 等身份配置变化后重新签发令牌。客户端原买家 ID 不因品牌更名自行替换；身份迁移需独立实施。

## 本地买家迁移

`scripts/migrate_local_buyer.py` 只在停服后用于明确的源/目标买家。它先通过 SQLite backup API 备份，再更新支持的权威库；目标已有记录时拒绝混合。新增覆盖 `purchase_records.sqlite3` 和 `trade.db`。最多同时附加数据库的限制由 SQLite 编译决定，超过时预先拒绝且不修改数据；双主库须先明确权威库与归档安排。

此脚本不迁移 Redis 任务、外部数据库或自然语言正文中的买家字符串，不自动更名数据库。多库写入期间必须保持停服；不要将其视为在线分布式事务工具。

## Compose 验收范围

基础 fixture 配置使用构建前端与 worker；CJ 叠加用 `!reset` 替换为单个预构建前端，worker 默认不启用。需 Docker Compose >= 2.24，并先生成 `frontend/dist`。Amazon/eBay 叠加需对应快照和中文投影文件。

本轮检查的是真实 Compose 合并输出、配置一致性和隔离回归；没有启动容器、迁移实际数据库、排空真实 Redis 或执行付费接口。这些部署步骤须在维护窗口按本说明验收并记录。
