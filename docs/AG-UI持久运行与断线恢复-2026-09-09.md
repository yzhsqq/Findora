# AG-UI 持久运行与断线恢复（2026-09-09）

同日后续更新：[刷新恢复修复](刷新恢复修复-2026-09-09.md) 已补齐缓存缺失时服务端恢复与当前导航保留，并在原用户标签页实测。使用固定页面地址保留演示买家身份；启动和数据保存位置见 [README](../README.md)。

正式服务现在将一次模型运行与浏览器的 SSE 订阅分开。网络断开、切换会话、页面卸载只停止读取事件；只有明确调用停止接口才请求取消模型。刷新页面可读取服务端历史，并恢复仍在执行的运行。

## 存储与执行

`Container.ag_ui_runtime` 使用 `data_dir/ag_ui_runs.db`，由 `AGUIJournal` 维护 SQLite WAL 日志。三个表分别保存买家绑定的会话、运行元数据/最新投影、按 `(run_id, seq)` 唯一排序的事件。追加事件与更新消息/商品状态投影在同一事务内提交，只有提交后的事件才会被 SSE 读取。并发首次建库对 WAL 锁冲突作有限重试；数据库失败不会退回假内存日志。

相同 runId 和请求内容重复提交只重放同一次运行，不再次执行模型；同 runId 改写需求返回 409。同一会话已有活动运行时拒绝并行创建另一轮。UI 历史以服务端消息为准，新请求只采纳最后一条 user 消息，不采纳客户端伪造的旧 assistant 历史或业务 state。

执行者持有持久租约（默认 30 秒，5 秒续期），日志写入检查 owner 和到期时间。远端实例收到明确停止请求时，先保存 stopRequested；拥有执行任务的实例会在心跳时发现并真正取消。前端等待服务端终态，停止请求网络失败时显示“尚未确认”，不会声称已经停止。

服务正常退出会取消活动模型并写入可重放的中断终态；进程突然消失时，后续读取会在租约到期后把孤立运行收口为 `RUN_ERROR / SERVER_RESTART`。已保存内容可查看，但不会假装恢复 Python/SDK 内部执行栈，也不会自动再次执行工具。明确停止收口为 `RUN_ERROR / CANCELLED`，正常完成为 `RUN_FINISHED`。终态禁止旧 owner 继续追加。

## HTTP 契约

| 接口 | 用途 |
| --- | --- |
| `POST /commerce/ag-ui/run` | 新建/幂等复用运行，返回标准 AG-UI SSE |
| `GET /commerce/ag-ui/runs/{run_id}/events?buyer_id=...&after=N` | 从第 N 条之后读取持久事件，并继续等待新事件 |
| `GET /commerce/ag-ui/runs/{run_id}?buyer_id=...` | 读取运行状态、最新投影和该轮有效输入 |
| `POST /commerce/ag-ui/runs/{run_id}/cancel?buyer_id=...` | 持久记录明确停止意图，并取消执行者 |
| `GET /commerce/ag-ui/sessions?buyer_id=...` | 返回该买家最近 100 段服务端历史摘要 |
| `GET /commerce/ag-ui/sessions/{session_id}?buyer_id=...` | 读取服务端消息、商品状态和最后运行 |

每帧 SSE 带 `id: {run_id}:{seq}`。恢复接口同时支持 `Last-Event-ID`，存在该头时优先使用；运行前缀不匹配、游标超过日志末尾返回 409，不能把另一运行的游标当作当前进度。事件 ID 和聊天消息 ID 分开：前者负责传输去重，后者供官方 SDK 更新消息。

所有接口调用 `require_buyer`；运行/会话接口进一步调用共享 `require_session`，并由日志再次校验 buyer/session 归属。严格身份模式使用 `Authorization: Bearer ...`，不把凭证放入 URL。默认 demo 模式的 buyerId 只是声明身份，不应被当作真实登录认证。前端可通过 `VITE_BUYER_ID` 指定匹配主体，令牌从配置或 `localStorage['findora.access-token']` 读取；浏览器内的凭证必须按实际部署的身份方案管理。

## 前端恢复行为

前端仍使用官方 `HttpAgent`，不自行实现 AG-UI 业务归约器。`recoveringFetch` 只负责 SSE 游标、重复过滤、顺序缺口和有限重连。网络中断后继续 GET 日志，绝不自动重复 POST 模型请求。重复帧忽略；乱序缺口从最后连续游标重读。恢复请求仍失败时保留本轮 ID，页面显示“恢复本轮 / 停止本轮”。

同一连接的暂时断线使用连续游标增量恢复。整页刷新会先读取服务端会话投影，再用新 SDK 实例从该轮事件起点重放，保留 START、工具调用等协议状态；这有意避免仅靠消息摘要恢复到半个工具参数流时破坏官方 SDK 的状态机。重放不会重新执行模型。

本机缓存保留最近 12 段，作为暂时无法读取服务端时的后备；页面明确提示历史服务不可用。切换已配置买家时不展示前一买家的旧本机消息缓存。清除浏览器的身份信息后，demo 随机 buyerId 也会改变，不能据此自动找回旧买家的记录；严格身份应使用稳定主体。

## 最终并发修复与专项回归

真实浏览器验收发现，明确比较 `P1001-S2 / P1003-S1` 时，模型可能并发发出两次精确商品查询，原先后一个结果会覆盖前一张卡。新增 `ProductCandidateProjection(raw_query)` 作为展示与末尾证据持久化的共同投影：仅最后一条 user 原文明确包含两个以上不同商品 ID、且本次结果为 exact_id_lookup 时合并，按原始 ID 顺序排序，指定 SKU 必须与卡片 default_sku_id 一致。完整 DTO 原样保留，不拼装价格、运费或图片。跨多个工具结果时使用 result_refs，不拿最后一条引用冒充完整合并结果。

每轮新建投影实例，不读取客户端旧候选；普通检索、条件变化和空结果仍替换并清除合并状态。由于现行 tool.result 不包含每次查询的 requested_identifiers，空精确结果也保守清空，不猜测哪个尚未返回的商品存在或不存在。重复结果不重复卡片，过滤拒绝的旧候选不保留。

另外，真实 SQLite 多实例初始化曾在 DDL 阶段偶发 database is locked。现在初始化重试覆盖 WAL 与建表整个过程，每次关闭连接重试；PRAGMA 结果游标显式耗尽和关闭，DDL 在 BEGIN IMMEDIATE/COMMIT 中完成。仅 locked/busy 重试，其他结构/IO错误原样失败。初始化 busy_timeout=500ms、最多20次并受8秒重试截止时间约束，最多允许当前一次数据库操作收尾；正常运行的读写连接超时不变。

```bash
uv run python -m pytest -q tests/test_ag_ui_journal_initialization.py \
  tests/test_ag_ui_journal.py tests/test_product_candidate_projection.py tests/test_ag_ui.py \
  --junitxml=/tmp/globex-journal-init-candidate-tests.xml
```

修复后本组 **56 passed in 4.22s**。其中 6 项商品投影测试包含真实 UseCase+真实工具并发逆序返回；22 项初始化测试包括连续20轮新数据库、每轮6个真实SQLite并发实例原子reserve，真实DDL写锁持有超过500ms后解除，以及损坏数据库不被当作锁冲突重试。该结果与前述初版28项报告分别记录，不将不同源码版本的报告混作同一次验证。

## 当前边界

- 正式 server 必须装配持久 `AGUIRuntime`。不传 runtime 的旧嵌入式 `stream_run`/路由保留原有非持久测试合同，不提供恢复能力；没有把它宣传为可恢复部署。
- journal 保存当前适配器生成的完整事件与 `STATE_SNAPSHOT` 投影；它不是任意 AG-UI 扩展事件的通用数据库。人工确认继续通过已有显式确认 API，`RunAgentInput.resume` 尚不支持 SDK interrupt 续接，网络重连与人工确认 resume 不混用。
- SQLite 文件必须位于持久卷；多个实例必须指向同一个可正确支持 SQLite 锁的本机文件。不同机器各自的 data_dir 不会自动同步，网络文件系统、多地域以及 PostgreSQL journal 尚未验证。
- 崩溃恢复的单位是已提交事件和终态，不是任意模型执行栈。模型/工具的跨系统副作用仍依赖各自确认和幂等事务。
- 事件和运行记录目前不自动裁剪，以保证游标可完整重放；长期部署需要另定归档、隐私保留期限与过期游标契约。前端恢复重试有上限，服务长期不可用会如实提示并保留恢复入口。
