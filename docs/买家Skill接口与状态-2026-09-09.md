# 买家 Skill 目录与读取状态

页面使用已发布方案目录与真实读取投影。买家显式选择通过结构化字段进入本轮请求，服务端在首个模型调用前确定读取指定版本；普通自然语言仍由 Agent 按需调用 Skill。没有改变 Prompt 工具合同、没有新增模型工具，也没有发布生产草稿。

## 目录接口

`GET /commerce/skills?buyer_id=<当前买家>` 沿用现有身份策略：严格模式要求匹配当前买家的 `Authorization: Bearer ...`；demo 模式可用正常买家标识。读取目录不会创建购物会话，也不接受 query 中的身份令牌。

```json
{
  "capability_digest": "当前有效能力集合的64位摘要",
  "skills": [
    {
      "id": "backpack-selection",
      "version": "1.0",
      "title": "周末背包选购",
      "description": "预算、轻便和配送目的地明确后，对比目录可证实的规格与商品价。",
      "scope": "shopping:backpack",
      "content_hash": "已发布内容的64位摘要",
      "expires_at": "2026-12-31T15:59:59+00:00"
    }
  ]
}
```

上例仅表示响应结构，**不表示生产已发布该方案**。无有效条目时返回 `skills: []`；草稿、未发布、已撤销、已过期、当前实际工具集无法支持的 Skill 都不返回，也不返回正文、审核人或证据内容。metadata 在同一读取事务中核对 digest，发布竞争返回409；服务未装配、损坏或不可读返回503，不能冒充空列表。身份失败保持401/403。

## 显式选择与确定读取

`POST /commerce/ag-ui/run` 的 `forwardedProps` 支持：

```json
{
  "buyerId": "当前买家",
  "selectedSkill": {
    "id": "backpack-selection",
    "version": "1.0",
    "contentHash": "从目录取得的64位小写十六进制摘要"
  }
}
```

`selectedSkill` 可整体省略；提供时必须且只能包含上述三个字段，不接受 `null`、客户端正文、工具列表或权限。id/version 使用能力库相同的 1–64 位 ASCII 标识格式，不做数字或布尔强制转换。格式错误返回 422。用户消息只包含需求正文，无需通过自然语言前缀传技术标识。

执行顺序是：持久会话 owner/fence claim → 当前买家与会话的 capability digest 绑定 → 用当前 Agent 实际 toolkit 白名单读取指定已发布版本 → 在读取事务复核 digest、发布状态、有效期、工具依赖和内容哈希 → 以 `authority=reference_only` 的独立消息交给当前 Agent → 首个模型调用。资料不能新增工具、提升权限、改写预算/禁忌或代替交易确认。每轮清除上一轮的 `selected_skill_reference` 原文提示，再按本轮选择加载，避免换选或直接提问时堆积旧方案。

显式选择禁用文本语义缓存。不存在、未审核发布、撤销、过期、hash 不一致、owner 不匹配、会话固定资料版本已变化或租约失效时，预读失败并结束本轮，不默默改成普通搜索；模型不会接收未校验正文。取消中的只读 SQL 线程可能完成本机读取，但不能再发成功状态或启动模型。

持久 run 指纹包含完整 `selectedSkill`，同一 runId 修改 id/version/hash 或移除选择都会返回 409。重连重放已存事件，重发同一已保留 run 不重复读取或执行模型。未选择时保持原运行指纹格式，兼容之前的运行记录。

## AG-UI 状态

`STATE_SNAPSHOT.snapshot.skillUsages` 是本轮真实读取记录，新 run 从空数组开始，不继承客户端伪造 state：

```json
{
  "toolCallId": "run-id:tool:call-id",
  "id": "backpack-selection",
  "version": "1.0",
  "title": "周末背包选购",
  "contentHash": "已读取内容的64位摘要",
  "status": "used"
}
```

status 为 reading / used / error。模型自主工具路径的 reading 在框架开始真实工具结果流时出现，可带已解析的 id/version；used 要求实际 ToolResultState.SUCCESS、有效 Skill 结果结构、id/version 与调用一致、内容 hash 格式有效。失败、版本不符、无法解析或中断都为 error，可带面向买家的 error 文案。title/hash 来自真实读取结果，不从选择卡或模型文字推测；正文不复制到该展示字段。

显式选择另带 `source: "server_preload"`，兼容展示键为 `toolCallId: "<runId>:preload:<operationId>"`，它是预读记录标识，**不是模型发起的 tool call**。reading 表示服务端已开始本次预读校验；used 只在权威库成功读取且哈希校验通过后出现。相同记录从 reading 更新为 used/error，另发送 `CUSTOM(name="skill.preload")`；不会生成伪造的 `TOOL_CALL_*` 事件。运行记录应显示“服务端已读取指定版本”，不能显示“模型调用工具成功”。

Trace 的真实 `commerce.skill.preload` span 使用 `retriever` 类型与 `findora.skill.source=server_preload`，仅携带 id/version/hash，不携带正文。它在首个 Agent/model span 前执行，与模型主动工具 span 的语义分开。既有 OTLP sanitizer 仍过滤原始资料内容。

`used` 的准确展示语义是“已成功读取该方案”，不证明模型逐条执行了正文，也不表示已下单。前端 local“已选择”应独立于服务端 reading/used/error。若重启恢复到 error/cancelled 终态时仍留有 reading，应展示“读取未完成”，不能继续显示运行中或改为成功。
