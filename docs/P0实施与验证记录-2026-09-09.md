## 实际运行的验证

- 完整后端回归：**616 passed，52.49 秒**，无跳过。使用隔离编译的官方 Redis 7.4.8，测试自行创建本地 Unix socket 进程，不连接或清空用户已有 Redis。
- 前端：**60 passed**，`npm run build` 通过。生产构建主应用约 49 kB，SDK 和 UI 依赖独立分块。
- `git diff --check` 通过。
- 真实 qwen3-max + AG-UI 搜索复验通过：3 张商品卡，首协议事件 83 ms、首文本约 4.73 秒、总计约 11.09 秒，标准生命周期/工具参数 JSON/最终状态均正确。证据：[AG-UI 报告](../eval/verification/ag-ui-trade-batch-20260909.json)。
- 浏览器使用独立库完成表单准备、批准、取消、模型准备、拒绝和刷新恢复：订单数始终不超过 1，库存 80→78→80；模型重启后查询同一会话也正确识别 CANCELLED。手机 390px 下内容宽 375px，无横向溢出、无控制台错误。证据：[交易报告](../eval/verification/trade-browser-20260909.json)。
- 被测服务 app 启动源码 hash 与当前应用源码 hash 匹配；该证据不等于依赖、数据卷或外部模型版本一致。
- 本地真实 OTLP HTTP 接收器验证父子 Span、认证/路径、SSE 生命周期和脱敏；测试模型回调使用本地夹具，不冒充真实 Langfuse 验收。
- 正式 release dry-run 实际选择商品/知识/Agent **45/15/30** 条，状态为 NOT_RUN；关键词 dev/release 分开实际执行，既有 all 150 条批准基线复跑 PASS。证据位于 [评测证据目录](../eval/verification/split-20260909/final/)。

1. **真实 Langfuse 看板**：本地配置/凭据尚未提供，已向用户询问配置位置。本机 collector 只证明协议、关联和脱敏，不能代替真实实例验收。
2. **正式在线发布门禁**：真实重排服务仍返回未找到模型服务，当前检索为 embedding_only。没有把降级结果记作 online-main 通过。还需为正式 Agent 交易场景加入显式确认动作步骤，再在隔离评测环境生成三份在线报告。
3. **完整恢复语义**：目前持久确认与终态可查；SSE 事件游标重放、跨进程会话持久 fencing/CAS 尚未完成。队列 Stream/终态记录的归档清理与实际故障转移验收仍需单独建设。

SQLite 事务已验证同机多连接/多进程；没有声明其他数据库或 Redis Cluster/故障转移等价保证。共享模型配额当前按主模型 scope 包含 retry/fallback，精确到每个上游 attempt/实际回退模型的配额归属仍保留在后续改进中。
